一条通知走完六步；其中第 3 步由程序做机械校验，第 4 步之后才有页面上的东西。
01 INPUT

输入

粘贴通知原文，上限 5000 字。空白/超长即时提示，不静默截断。

→
02 MODEL

模型解析

WorkBuddy 云服务免密钥通道，deepseek-v4.1-flash 流式返回固定 JSON。

AI

03 VALIDATE

程序校验

字段与类型、status 取值、missing 不得填值、每条引文必须能在原文逐字找到；required 必须有依据。

程序（确定性）
→
04 STATE

状态标注

stated / missing / unclear / conflict 四态，逐项对应原文；冲突并列保留。

程序
→
05 RENDER

展示与复制

行动卡按用途分时间与地点；勾选状态进入复制文本；全部走 textContent。

浏览器
→
06 HUMAN

人核对

展开「对照通知原文」，逐项比对后转发给长辈；不替用户办理任何事。

人

! 校验不通过怎么办

自动重试 1 次；仍不通过 → 显示「这次没有整理成功。原文还在，可以再试一次。」不渲染行动卡。宁可不出，也不出错卡。

? 校验通过 ≠ 语义正确

机械校验只能发现"引文对不上原文""结构缺字段""标了要求却没有依据"，不能保证理解一定正确。所以卡片始终提示以原文为准。
