## 五、部署要点（避免踩坑）

1. **必须复用同一应用**：新建应用会换域名，模型通道 Origin 不匹配，全部调用会被拒。
2. **静态资源带版本号**：`index.html` 里的 `?v=1.1.0-a3` 是给 CDN 的缓存键。改前端后**必须同步改这个版本号**，否则会出现「HTML 是新的、JS 是旧的」的混合状态（A 轮实测踩到过，表现为页面样式变了但功能丢失）。
3. **发布后要等传播**：平台上同一域名在不同节点可能短时返回不同版本。验证方法：
   ```js
   // 连续刷新 5 次，每次执行
   window.MBB_CONFIG.appVersion   // 应始终为同一个值
   ```
4. **测试脚本要等就绪**：`tools/*.cjs` 里都加了 `readyPage()`，会等待 `window.__MBB` 出现并核对版本号，最长重试 4 次。

## 六、模型与数据

| 项 | 实际情况 |
|---|---|
| 通道 | WorkBuddy 云服务免密钥大模型通道（浏览器直连数据面，服务端按 Origin 校验） |
| 运行时模型 | `deepseek-v4.1-flash`（由模型列表接口读取后选用，页脚显示实际模型名） |
| 参数 | 流式、temperature 0.1、单次超时 45 秒、失败最多重试 1 次（网络瞬断也重试 1 次） |
| 数据 | 不建账号、不建历史库、不主动写日志；通知原文只在本次请求中使用 |
| 不承诺 | 平台侧对请求数据的处理不在本产品控制范围，因此不说「绝不保留」 |
