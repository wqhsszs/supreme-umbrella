# 16｜C 轮新增功能与限制（v1.3.0-c7）

> **本轮实测汇总**：C1 截图识别 20/20；C2 朗读 19/19；布局（360/390/768/1280，三态）通过；A 轮回归本版重跑：12 条用例 11/12（N1 网络瞬断）、页面行为 9/10（E1 判据文案，已修未复跑）、A 轮专项 11/11。
> **录屏与朗读原声已于 2026-10-24 补录完成**：演示视频为**真实操作录屏**（有界面 Edge + CDP 抓帧，153 秒），朗读段声音来自产品在同一台机器上的真实播放（WASAPI 环回录制，截取约 18 秒）。

> 本文只讲 C 轮新增的两项能力：截图识别（C1）与行动卡朗读（C2）。
> 三个问题分别回答：实现到什么程度、哪些环境验证过、哪些没验证。
> 所有数字来自 `assets/evidence/` 的原始记录，写法与 A/B 轮一致。

## 一、C1 截图识别 + 人工核对

### 实现到什么程度

| 环节 | 程度 | 说明 |
|---|---|---|
| 入口 | 已实现 | 首页两个标签：「粘贴文字」「上传通知截图」，文字粘贴保留 |
| 文件边界 | 已实现 | JPG/PNG/WebP、≤8MB、长边缩到 1600px；HEIC 明确提示不支持并给出处理建议 |
| 取字 | 已实现 | 多模态模型独立调用（专用 `prompts/ocr-prompt.txt`）：逐字提取、保留段落、不改写不补全、不给置信度；看不清标「［此处看不清，请对照图片］」 |
| 对照界面 | 已实现 | 左原图（可点开大图）右文字双栏；手机上下排、桌面并排 |
| 核对闸门 | 已实现 | 必须勾选"我已核对"才能整理；文字一改，勾选自动取消，旧卡片、复制文本、朗读全部作废 |
| 来源标记 | 已实现 | 卡片页首标"文字由 <模型> 取出后经整理者核对"；证据入口写「对照核对后的通知文字」，与文字来源的「对照通知原文」区分 |
| 失败路径 | 已实现 | 无字、太模糊、超时、坏文件、超 8MB、无识图模型：全部停留在原图页，给出下一步（换图 / 改用粘贴），保留用户输入 |
| 超长处理 | 已实现 | 识别文字超过 5000 字：提示分段处理，不截断、不继续生成 |
| 恶意指令 | 已实现 | 图中"忽略规则"类文字只作为数据取出；整理提示词与校验层不执行 |
| 隐私 | 已实现 | 图片只存在于当前页面内存（ObjectURL + dataURL），不写 localStorage/sessionStorage/IndexedDB，不发往除模型通道外的地址 |

### 验证过什么

- **C1 专项 20 项全部通过**（2026-10-23，线上 v1.3.0-c7，Edge 390×844，真实模型调用）：清晰通知取字零添改、无年份无地点不补、冲突两处全保留、模糊图不编数字、空白图/聊天截图、人工把 8:3O 改成 8:30 后卡片以改后文字为准、图内指令不改变结论、长文不截断、个人信息不落库、坏文件/超大文件、取字中取消与换图、核对闸门与改字作废、超限提示。
- **布局**：上传/预览/核对三态在 360/390/768/1280 无横向滚动；触控区 ≥44px；核对页桌面并排、手机堆叠。
- 原始记录：`assets/evidence/c-ocr-*.json`（20 项，含每次真实取字文本）；测试图与逐句对照见 `assets/ocr-samples/` 与 `tools/gen_ocr_samples.py`。

### 没验证什么

- 真实手机相机拍照（本测试用的是程序排版的清晰截图）；手写体、印刷体模糊照片只测了一张低对比度样本。
- 真人核对习惯：没有用户试用数据。
- 部分低端安卓浏览器（例如微信内置 X5 内核）的 `createImageBitmap` 行为未实测，代码里已降级到 `Image` 解码。

## 二、C2 行动卡朗读

### 实现到什么程度

| 项 | 程度 | 说明 |
|---|---|---|
| 入口 | 已实现 | 卡片内独立卡片「读给家人听」，不自动播放 |
| 控制 | 已实现 | 暂停/继续（同一按钮切换）、停止；换通知、改文字、离开页面自动终止 |
| 单实例 | 已实现 | 连续点击只保留最新一次；换卡时旧朗读作废 |
| 文本 | 已实现 | 从已校验数据确定性拼接：事项、对象、各用途时间+地点、准备、下一步、仅限条件、待确认、注意全读；"通知未说明/前后不一致"照读；勾选读成"整理者已勾选 N 项，不代表已经报名" |
| 发音 | 已实现 | 等价改写：9:00→9点、9:00—11:00→9点到11点；数值、年份、用途不变；无年份不读年份 |
| 音色 | 已实现 | Web Speech API，按提示词偏好挑中文音色（本机 Microsoft Huihui）；`canDisableThinking` 类参数不存在，未编造任何云端 TTS 参数 |
| 降级 | 已实现 | 浏览器不支持、无中文音色、合成失败：分别给出可读提示；不显示假成功 |
| 下载语音 | **未实现** | Web Speech API 无法导出音频文件，界面不提供"下载语音"按钮（任务书允许：只有真实生成成功才显示保存入口，此处属通道能力缺失，如实记录） |

### 验证过什么

- **C2 专项 19 项全部通过**（同环境）：发音改写不变值、三张卡（完整/缺失/冲突）内容检查、无 JSON/网址/按钮名、勾选表述、暂停/继续/停止状态、单实例、换卡终止、无音色与不支持提示、真实引擎可取到中文音色并接受合成。
- **原声录制：已完成（10-24 补录）。** 用 WASAPI 环回（`tools/record_p6_audio.py`）+ 有界面 Edge，录下产品真实播放的朗读（18.53 秒），存在 `assets/audio/speech-live.wav`，并已混入演示视频。C2 仍只验证文本与状态机，声音质量没有真人试听结论。
- 朗读文本快照与页面一致：`c-speech-*.json` 内含三张卡的实际朗读全文。

### 没验证什么

- 声音的"好听程度"与语速是否适合长辈：没有真人试听数据，材料里不写任何满意度。
- 微信内置浏览器、iOS Safari、安卓小厂浏览器的 Web Speech 兼容性：只在本机 Edge 验证。
- 蓝牙音箱/免提播放路径：未测。

## 三、模型与通道的真实分工（避免误读）

| 能力 | 实际用的是什么 |
|---|---|
| 截图取字 | `minimax-m3.1-flash`（原生多模态），**实测 `image_url`+base64 可用后接入**，目录里按 `supportsImages` 过滤 |
| 事实整理 | 同模型、第二次独立调用（`system-prompt.txt`） |
| 机械校验 | 自研 validate.js（非 AI） |
| 产品内朗读 | 浏览器 Web Speech API（**非云端 TTS**，无音频导出能力） |
| 视频旁白 | Windows SAPI5（材料制作用，与产品内朗读是两个通道） |

材料里不写"接入了 OCR 引擎"这类话——识图与整理用的是同一个模型的两次调用，这一事实已在 12 号文件与五步图中分开标注。

## 五、部署与外部依赖（本轮实测）

- **SDK 已改为本地优先**：页面先加载 `js/vendor/workbuddy-cloud-sdk.global.js`（与 CDN 同一个 UMD 文件），本地缺失时才回退 `cdn.jsdelivr.net`。原因是本轮多次遇到 CDN 不可达导致"页面半载、SDK 未加载"。
  线上核对：`/js/vendor/workbuddy-cloud-sdk.global.js` 返回 **200**；首页 HTML 的 Last-Modified 已更新为 2026-10-24 03:24 UTC（带 `&cb=` 参数可绕过边缘缓存看到新版）。
- **首访自动重载一次**：若首次访问时配置脚本没加载成功（分享 Cookie 尚未落地 / 边缘层偶发 5xx），`index.html` 末尾会自动重载一次（sessionStorage 防循环）；第二次仍失败则显示"页面没有加载完整，请刷新"。
- **分享链接的纯 URL 有边缘缓存**：不带 `cb` 参数直接打开时，可能仍拿到上一版 HTML（约半小时级 TTL）。带任意查询参数（例如 `?sharecode=...&cb=1`）即可拿到新版；强制刷新（Ctrl+F5）同理。
- **模型对话接口**：`deepseek-v4.1-flash` 曾对该应用持续返回 403（模型列表正常）；换用 `minimax-m3.1-flash` 后恢复。如再遇单模型 403，按第 6 节更换 `preferredModelHints` 即可。

## 六、运行时模型变更（2026-10-24）

原选用的 `deepseek-v4.1-flash` 对该应用持续返回 **HTTP 403**（`llm.models.list()` 正常、`chat/completions` 403），同一应用下 `minimax-m3.1-flash`、`kimi-k2.6`、`glm-5.3-flash`、`hy3`、`auto` 均正常。
最终运行时改用 **minimax-m3.1-flash**（原生多模态，`supportsImages: true`，取字约 5.5 秒、整理约 6–12 秒，识图与 JSON 均实测通过），并在 `js/config.js` 的 `preferredModelHints` / `ocr.modelHints` 中把 kimi-k2.6、glm-5.3-flash 列为后备。
`assets/evidence/capability-probe.json` 记录的识图格式核实仍以 deepseek 为对象，属历史事实，不改写。

## 七、本轮没有做到的（明确列出）

- **目标用户试用未开展**：没有长辈或志愿者使用本版本的记录，因此没有任何效果、满意度、节省时间的数据。
- **真机未测**：四档视口都是桌面浏览器模拟；微信内置浏览器、iOS Safari、安卓低端机的取字与朗读表现未验证。
- **不能导出音频**：产品内朗读用浏览器 Web Speech API，无法导出文件，界面不提供"下载语音"。
- **手写体 / 严重倾斜拍照件**：只测了一张低对比度样本，不给结论。
- **云端 TTS**：当前通道不存在，产品如实降级；若平台未来提供再评估"保存这张卡的语音"。
