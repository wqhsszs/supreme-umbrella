# 配对任务卡与访谈提纲（C 轮：含截图识别与朗读）

> 用法：一位整理者（家人/志愿者）+ 一位接收者（长辈）。先做 A 条（直接看/听），再做 B 条（用产品），或按编号奇偶交替顺序。
> 全程不超过 25 分钟。整理者可以帮忙操作手机，但不能替接收者读卡片内容。
> 本版新增两条与 C 轮功能直接相关的任务：核对识别文字、听产品朗读。

## 准备

- 一部能上网的手机（或平板），打开 https://mingbaiban-42482.app.workbuddy.host/
- 两条难度相近、内容不同的通知，编号 A / B：
  - **每条都准备成截图**（从聊天记录或照片裁出来），这是真实使用形态
  - 其中至少一条要故意有"看不太清"的地方（反光、虚一点），用来观察核对环节
- 计时器、记录表 `02_试用记录表_空白.csv`
- 耳机（可选）：朗读环节如果环境吵，用耳机听

## 任务一：直接看/听（对照组，通知 A）

把通知 A 的截图直接给接收者，让接收者自己看一遍（或让家人读），然后回答：

1. 什么时候之前要报名？
2. 活动是哪天、几点到几点？
3. 报名去哪里？活动去哪里？
4. 要带什么？
5. 谁能参加？

> 记录：答对几项（5 项里）、用时、是否需要人念。

## 任务二：用产品（实验组，通知 B）

整理者操作，接收者在旁边看：

1. 切到「上传通知截图」，选通知 B 的截图，点「识别文字」。
2. **核对环节（重点观察）**：让接收者也看着屏幕，问"右边这几个字，和图上一样吗？哪里不一样？"
   - 记录：识别错了几个字、谁发现的（接收者/整理者）、改没改、改完有没有重新核对。
   - 若出现"［此处看不清，请对照图片］"，问接收者："这个地方该怎么办？"
3. 勾选"我已核对"，点「已核对文字，整理行动卡」。
4. **把手机交给接收者**，让接收者自己看卡片，回答同样 5 个问题。
5. **朗读环节**：问接收者"想不想让它读给你听？"（不要主动替他点）
   - 点「读给家人听」后：记录有没有听清"报名截止 17 点""地点在一楼""仅限已报名""通知未说明"这几处；中途问一次"刚才说的要带什么？"
   - 观察会不会自己按暂停/停止。
6. 卡片上打勾的方框，接收者认为代表什么？（关键理解点：**打勾≠已报名**）

> 记录：答对几项、用时、是否需要人念、是否点开"对照核对后的通知文字"、对"未说明"的理解、对朗读的评价（用自己的话说）、对打勾的理解。

## 给整理者的问题（试用后，3 分钟）

1. 传截图这个方式，比打字贴文字省事吗？哪里别扭？
2. 核对识别文字时，你最担心什么？AI 取错字你发现了吗？
3. "读给家人听"这个声音，长辈听得清吗？数字（比如 17:00）听清楚了吗？
4. 你会把这张卡怎么发给长辈（听 / 复制文字 / 截图）？
5. 这个工具你会在什么情况下不用它？

## 给接收者的问题（试用后，2 分钟，避免诱导）

1. 卡片上你最先看哪一行？
2. 刚才读给你的声音，哪句话没听清？
3. 如果明天还有一条通知（也是截图），你愿意自己传上来试吗？
4. （不要问"是不是很方便""是不是比原来清楚"，这类问题答不出信息）

## 记录口径

| 字段 | 说明 |
|---|---|
| 答对项数 | 0—5，对照任务一的 5 个问题 |
| 用时 | 从拿到材料到说完答案 |
| 求助次数 | 主动求助 + 卡住超 60 秒给的提示，各记 1 |
| 是否需要人念 | 是/否；"是"不算失败，是重要发现 |
| 识别错误 | 取出的文字里，错的字数与被谁发现 |
| 是否点开对照 | 是/否/未观察（截图来源显示"对照核对后的通知文字"） |
| 对朗读 | 是否听清关键数字与"未说明"（能复述 = 听清） |
| 对打勾的理解 | 正确（只是准备）/ 误解（以为已报名）/ 未问 |
| 原话 | 直接抄，用引号，不改写 |
